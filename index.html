The avalanche effect

Change one character and about half of the 256 output bits flip. That unpredictability is why hashes can't be reversed by nudging the input.

bit differs · bit matches (SHA-256)

Why it matters
  • Hashes are one-way fingerprints used for integrity checks, digital signatures, content addressing (Git!) and password storage.
  • SHA-1 is broken for collision resistance (the 2017 SHAttered attack). Use SHA-256 or better.
  • Never store passwords with a fast hash like SHA-256 alone. Use a slow, salted KDF (bcrypt, scrypt, Argon2 or PBKDF2) so each guess costs attackers real time.

What's happening
  • Key derivation: PBKDF2-HMAC-SHA256 with a random 16-byte salt and 600,000 iterations (OWASP 2023) turns a password into a 256-bit key. The salt defeats precomputed rainbow tables.
  • AES-256-GCM: authenticated encryption. A random 12-byte IV means the same message encrypts differently every time, and a 128-bit authentication tag detects any modification before a single byte is decrypted.
  • Bundle format: v1.salt.iv.ciphertext in base64url. Everything needed to decrypt except the password.
